# TODO：Importer 的硬编码解析与 LLM 校验/兜底

## 背景

当前 `importer.py` 主要依赖固定文件名、Markdown 标题层级和正则表达式推断论文元数据。该方式实现简单、可重复、无需联网，但容易受到 MinerU 输出格式、文档头部内容和作者排版差异的影响。

## 方案判断

该方案总体合理，适合作为渐进式增强：

1. 先使用硬编码规则完成文件定位和基础字段解析；
2. 对规则结果进行确定性校验；
3. 仅在字段缺失、格式异常或校验不通过时调用 LLM；
4. 让 LLM 判断候选结果是否合理，并返回结构化的修正建议；
5. 保留原始内容和规则结果，便于审计与回溯。

LLM 应主要承担“校验、纠错和兜底”职责，而不应直接覆盖原始 PDF、MinerU 输出或未经校验的元数据。

## 建议流程

```text
MinerU 输出目录
    -> 固定规则定位 full.md / content_list.json / PDF
    -> 规则解析 paper_id / title / authors / year
    -> 确定性校验
         |- 结果完整且合理：直接采用
         `- 缺失、冲突或置信度不足：调用 LLM
    -> 校验 LLM 输出格式和字段范围
    -> 生成最终 metadata.json
```

## 硬编码解析层

硬编码规则继续负责：

- 定位必需文件和候选 PDF；
- 复制文件并计算 SHA-256；
- 生成稳定的 `paper_id`；
- 从结构化元数据或 Markdown 中提取候选标题、作者和年份；
- 在输出目录已存在时拒绝覆盖。

建议将规则结果保存为候选值，并记录来源，例如：

```json
{
  "title": {"value": "...", "source": "markdown_h1"},
  "authors": {"value": ["..."], "source": "markdown_author_line"},
  "year": {"value": 2025, "source": "metadata_or_regex"}
}
```

## 确定性校验

在调用 LLM 前先检查：

- `paper_id` 是否为空、是否合法、是否与目录或已有标识冲突；
- 标题是否只是 `arXiv` ID、DOI、文件名或通用占位符；
- 作者是否疑似被解析成摘要、副标题、机构或日期；
- 年份是否处于合理范围，并且是否来自引用文献而非论文元数据；
- `full.md` 与 `content_list.json` 是否可读取且符合预期结构；
- 候选 PDF 是否存在且确实是文件。

## LLM 兜底与校验

LLM 输入应包含：

- 规则解析得到的候选字段；
- `full.md` 开头的有限上下文；
- MinerU 的结构化元数据（如果存在）；
- 文件名、目录名和可识别的 DOI/arXiv 信息。

LLM 输出应采用严格 JSON，并至少包含：

```json
{
  "decision": "accept|correct|uncertain",
  "paper_id": "...",
  "title": "...",
  "authors": ["..."],
  "year": 2025,
  "field_sources": {
    "paper_id": "...",
    "title": "...",
    "authors": "...",
    "year": "..."
  },
  "feedback": ["..."]
}
```

LLM 结果必须经过本地 schema 校验。对于 `uncertain`、字段缺失、JSON 格式错误或无法提供依据的结果，应保留规则结果并标记为待人工确认，而不是盲目覆盖。

## 需要特别处理的当前风险

- 第一行一级标题可能是 `# arXiv:...`，导致 arXiv ID 被当成标题；
- 标题后的第一行不一定是作者；
- 作者名可能使用单空格、换行、上标或机构标记；
- 第一个四位年份可能来自参考文献、DOI 或版权信息；
- 目录中存在多个 Markdown、PDF 或 content list 时，当前选择可能不稳定；
- `content_list.json` 当前缺少完整的输入 schema 校验；
- LLM 调用会带来成本、延迟、隐私和不可重复性问题；
- 不能让 LLM 修改 `raw/` 层或替换原始证据。

## 实施顺序

1. 把当前推断结果改成带 `source` 和 `confidence` 的候选结果；
2. 增加确定性字段校验和明确的 warning；
3. 增加 `ImporterMetadataReview` 的结构化输出模型；
4. 接入可选的 LLM 校验/兜底模式，默认仍可离线运行；
5. 对低置信度结果写入人工复核清单；
6. 增加 arXiv、DOI、标准论文标题、复杂作者列表和引用年份等测试；
7. 在导入清单中记录规则结果、LLM 决策、最终值和调用时间。

## 完成标准

- LLM 不可用时，规则导入流程仍可正常工作；
- LLM 不能覆盖原始 PDF、MinerU 文件或证据记录；
- 每个最终元数据字段都能追溯到规则来源、LLM 建议或人工输入；
- 结构化输出错误时不会破坏导入流程；
- 对标题、作者、年份的典型误判有自动化测试覆盖；
- 用户可以通过显式参数覆盖自动推断结果。
